# Проектная работа "WebLarek. Плохой сервер.", спринт 17

## Подготовка к работе

1. Склонировать репозиторий
2. Запустить docker

```bash
docker compose up -d
```

3. Наполнить базу данных
   [README.md](.dump%2FREADME.md)
4. Перейти по адресу http://localhost/ и на странице должны быть продукты.
5. На странице http://localhost/login/ можно авторизоваться.
6. Админка находится по адресу http://localhost/admin/

## Что исправлено

- XSS: пользовательский ввод очищается на сервере (sanitize-html), комментарий к заказу на клиенте превращается в простой текст, в интерфейсе нет `dangerouslySetInnerHTML`.
- CSRF: токен выдаёт `GET /csrf-token` (и `GET /auth/csrf-token`), клиент отправляет его в заголовке `X-CSRF-Token` во всех POST/PATCH/DELETE-запросах, сервер проверяет токен (csurf).
- NoSQL-инъекции: входные данные проходят валидацию Joi (celebrate), фильтр `status` и поля сортировки ограничены списками, в обновление пользователя попадают только разрешённые поля.
- Переполнение буфера: лимиты длины строк и размеров массивов в Joi, лимит тела запроса 1 МБ, лимит файла 10 МБ, ограничение `limit` в пагинации.
- ReDoS: регулярное выражение телефона заменено на безопасное, поисковая строка экранируется и обрезается до 50 символов.
- DDoS: rate limiting в Express (`express-rate-limit`) и в nginx (`limit_req`), кэширование списка товаров и статики, `error_log` nginx уровня `warn`.
- Path Traversal: статика отдаётся через `express.static`, имя файла картинки проверяется по шаблону, удаление файлов ограничено папкой `public`.
- Пароли хранятся в bcrypt, срок жизни токенов сокращён, секреты вынесены в `.env`.
- `npm audit` в `backend` и `frontend`: 0 уязвимостей, ESLint и сборка проходят без ошибок.
